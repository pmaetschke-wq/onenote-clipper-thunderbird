OneNote Clipper – Settings

This add-on talks directly to Microsoft only (login.microsoftonline.com and graph.microsoft.com). No third-party server is involved. It requires your own free app registration in Microsoft Entra ID.

Setup (one time, ~5 minutes)

  1. Personal account (@outlook.com etc.)? You first need your own Entra directory: create a free Azure account (card is only for identity verification, no charges – the add-on uses no paid Azure resources). Work/school accounts can skip this and use their existing directory.
  2. Open entra.microsoft.com → Entra ID → App registrations → New registration.
    Name: e.g. OneNote Clipper. Account types: Accounts in any organizational directory and personal Microsoft accounts (or "personal accounts only" for private use).
  3. Redirect URI: choose platform "Mobile and desktop applications" (NOT "Web"!) and enter exactly this URL as a custom redirect URI:

  1. API permissions → Add a permission → Microsoft Graph → Delegated → add Notes.ReadWrite (you consent yourself at first sign-in).
  2. Copy the Application (client) ID from the app's overview page into the field below and save.
  3. Open an email → OneNote Clipper button → Sign in with Microsoft.

Why "Mobile and desktop applications"? A redirect URI of type "Web" makes the app a confidential client that requires a client secret – a local add-on cannot have one (error AADSTS70002/AADSTS7000218). As a public client, no secret is needed.

Connection

Your data

Sign-in tokens and the section list are stored only locally in your Thunderbird/Betterbird profile (storage.local). "Sign out" deletes them.

Documentation

What is this? What can it do?

OneNote Clipper saves the currently opened or selected email(s) as OneNote pages with one click – similar to Outlook's "Send to OneNote", but for Thunderbird and Betterbird. Unlike solutions that route your data through a third-party server, this add-on talks directly to Microsoft. Your own app registration means you can revoke access at any time.

  • Page includes From/To/Date/Subject, formatted body (HTML or plain text), inline images and optionally attachments
  • Target section selectable, grouped by notebook, with live search filter
  • Last used section is remembered; multi-select saves several emails in one go
  • Success message links directly to the created OneNote page
How does it work technically?

Authentication

OAuth 2.0 authorization code flow with PKCE as a public client (no client secret), via browser.identity.launchWebAuthFlow. Scopes: Notes.ReadWrite, User.Read, offline_access (refresh token for silent renewal). Tokens live only in storage.local. Two workarounds are built in: prompt=select_account so the window does not vanish instantly with an existing Microsoft session, and removal of the Origin header only for login.microsoftonline.com (otherwise error AADSTS90023, because Microsoft rejects cross-origin token redemption for native clients). A tab-based fallback sign-in (paste-the-redirect-URL) is available from the popup.

Reading the email

The raw message (messages.getRaw) is parsed by the add-on's own MIME parser (mime.js): nested multiparts, base64, quoted-printable, 7bit/8bit, charsets (UTF-8, ISO-8859-1, Windows-1252, …), RFC 2231 filenames, inline images (cid:) and attachments. messages.getFull() is deliberately not used because it does not reliably return bodies across versions.

Creating the OneNote page

The HTML body is sanitized (scripts, forms, event handlers etc. removed) and serialized as well-formed XHTML. A header table is added, cid: references are rewritten to binary parts, and everything is posted as a manually built multipart/form-data request to POST /v1.0/me/onenote/sections/{id}/pages (Microsoft Graph). Sections are listed via GET /me/onenote/sections?$expand=parentNotebook and cached locally.

Tests

The parser and the full clip pipeline (raw email → sanitized page → multipart request) are covered by unit and integration tests run against realistic sample messages, including umlauts, nested multiparts, inline images and attachments.

Troubleshooting
ErrorFix
"Account not found in tenant 'Microsoft Services'" Personal account without a directory: create a free Azure account first (step 1 above).
AADSTS70002 / AADSTS7000218 (client_secret required) Redirect URI registered as "Web". Delete it and re-add it under "Mobile and desktop applications".
AADSTS90023 (cross-origin token redemption) Update the add-on (Origin workaround is built in since v1.2). Alternatively, register the redirect URI as "Single-page application".
AADSTS50011 (redirect_uri mismatch) The registered URI differs from the one shown above – copy it exactly, including https:// and the trailing /.
Sign-in window closes instantly Usually not an error: with an existing Microsoft session the window redirects immediately. Check the popup for the result. If it persists, use "Alternative tab-based sign-in" in the popup.
No message found Click/open the email again, then reopen the popup. Works with message tabs, standalone message windows and selections in the mail list.
Section list empty or outdated Click "Refresh sections" in the popup. On permission errors, verify Notes.ReadWrite (delegated) in the app registration.
Limits, privacy & warranty
  • ~20 MB total per page for inline images + attachments (larger items are skipped and listed in the result message).
  • Page title = email subject (max. 200 characters).
  • Encrypted emails (S/MIME/OpenPGP) may not always have a readable body.
  • No telemetry, no tracking, no update backend, no third-party servers. Signing out deletes all local tokens; deleting the app registration in Entra revokes all access immediately.
